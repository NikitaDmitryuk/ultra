# Happ и домашний прокси

## Старые конфигурации

Обновление ultra не требует перевыпуска основного TCP/REALITY/Vision-профиля:
сохраняются `public_host`, `vless_port`, UUID, REALITY-ключи, SNI и short IDs.
Не меняй эти поля при включении новых listeners. Старые `/client` и основные поля
ответа сохраняются. Новый `entry_id` равен `primary`; ID основных профилей прежние.
Источник: [экспорт и проверки совместимости](../internal/config/profile_integration_test.go).

Ранее выдававшийся XHTTP-профиль без настроенного listener никогда не был рабочим
резервом; теперь он не публикуется. Уже работающий XHTTP/REALITY на отдельном порту
сохраняет путь и REALITY-параметры. Старое игнорируемое `xPaddingSize` означало стандарт
ядра 100–1000; новый диапазон должен включать эти значения.

## Подписка

1. Настрой HTTPS бота по [канонической инструкции TLS](../deploy/TLS.md).
2. На тестовом VLESS-пользователе в Mini App нажми «Выдать / заменить подписку».
3. Сохрани показанную ссылку. «Открыть в Happ» открывает HTTPS-страницу ultra
   во внешнем браузере; на ней нажми «Добавить в Happ». Если приложение не открылось,
   скопируй ссылку и добавь подписку в Happ вручную.
4. Обнови подписку, выбери основной профиль, затем проверь доступный резерв вручную.

Прямой `happ://` внутри Telegram WebView может не открыться. Используется
[openLink](https://core.telegram.org/bots/webapps#initializing-mini-apps) для своей
HTTPS-страницы с отдельным нажатием на deep link. Токен передаётся во фрагменте URL
и удаляется из истории страницы; сторонние сервисы перенаправления не используются.
Источник: [страница импорта](../internal/bot/embed/miniapp/happ.js).

Публичный endpoint требует TLS. При TLS termination на reverse proxy бот принимает
`X-Forwarded-Proto: https` только от loopback; proxy должен перезаписывать этот заголовок.

Ссылка — секрет. Она показывается только при выпуске или ротации; повторный выпуск
закрывает прежнюю ссылку. «Отозвать подписку» запрещает обновления, но уже скачанные
конфиги продолжают работать. Для отзыва доступа к VPN отключи пользователя или смени UUID.
Подписка не требует платного provider ID. Автоматический выбор при запуске Happ
не гарантирует переключение уже открытого соединения.
Источники: [API](../internal/adminapi/subscriptions.go),
[Happ app management](https://github.com/HappDev/happ_su/blob/main/dev-docs/app-management.md),
[ADR](adr/0003-happ-subscription.md).

## Дополнительные listeners

`anti_censor.public_xhttp_port` включает XHTTP/REALITY. Новый `public_xhttp_tls`
задаётся в spec bridge отдельно; основной порт сохраняется:

```json
{
  "public_xhttp_tls": {
    "port": 8443,
    "server_name": "vpn.example.com",
    "certificate_file": "/etc/ultra/public/fullchain.pem",
    "key_file": "/etc/ultra/public/key.pem",
    "path": "/connect",
    "mode": "stream-up"
  }
}
```

Это фрагмент spec, не готовая установка. Домен должен указывать на доступный вход,
сертификат — покрывать `server_name`; файл ключа доступен только пользователю relay.
Listener использует H2 и не использует Vision. Выпуск сертификата, firewall и обновление
рабочего spec выполняются отдельным этапом по инструкциям установки.
`mode: packet-up`, `xmux` (поля закреплённого Xray) и `download` с `address`, `port`,
`server_name` — только для отдельных испытаний. Download-адрес должен обслуживать тот же
путь и пользователей, с проверяемым TLS; поле не создаёт удалённый listener автоматически.
Экспорт `extra` сохраняет эти параметры, но их сохранность после импорта в Happ требует проверки.
Источник: [общие настройки клиента/listener](../internal/config/xhttp_tls.go).

Резервный вход добавляется только после проверки уже созданного TCP passthrough:

```json
{"public_entries": [{"id": "backup", "host": "backup.example.com", "tcp_port": 443}]}
```

Опциональные `xhttp_reality_port` и `xhttp_tls_port` публикуют forwarding для соответствующего
listener bridge. Значение `0` исключает профиль. UUID и SNI сохраняются; новый ID имеет
вид `backup/fast_tcp_reality`. См. [решение о топологии](adr/0004-reserve-topology.md).

## Домашний Linux-сервер

Создай отдельного VLESS-пользователя ultra и сохрани его ответ `/client` в закрытый файл.
`ultra-client` принимает этот JSON, старый ответ с `full_xray_config_base64` либо полный
JSON Xray. Сборка: `make build-client`; для другого хоста используй `GOOS=linux` и его `GOARCH`.

```sh
./ultra-client -config client-export.json -profile fast_tcp_reality
curl --proxy socks5h://127.0.0.1:10808 https://api.ipify.org
curl --proxy http://127.0.0.1:10809 https://api.ipify.org
```

SOCKS5 и HTTP слушают только loopback. `socks5h` передаёт имя назначения прокси;
SOCKS5 с предварительным локальным DNS может вернуть неправильный адрес до входа в туннель.
Для сервисов используй `ALL_PROXY=socks5h://127.0.0.1:10808` либо
`HTTPS_PROXY=http://127.0.0.1:10809` и `HTTP_PROXY=http://127.0.0.1:10809`.
Поддержка переменных зависит от приложения; `NO_PROXY` создаёт прямые исключения.
Проверяй фактический выход и доступность Gemini, а не только запуск процесса.

Для постоянной работы скопируй бинарник в `/usr/local/bin/ultra-client`, создай системного
пользователя/группу `ultra-client`, каталог `/etc/ultra-client` с правами `0750` и файл
`client.json` с правами `0640`, доступный этой группе. Установи
[unit systemd](../deploy/ultra-client.service), затем выполни `systemctl daemon-reload`
и `systemctl enable --now ultra-client` **на своём домашнем сервере**.
`Restart=on-failure` восстанавливает процесс. Для резерва задай другой `-profile`
через override `ExecStart` и явно перезапусти unit; скачанные конфиги автоматически не обновляются.

`-render output.json` создаёт новый файл `0600` для самостоятельного запуска Xray.
Публичный SOCKS bridge не нужен. Для контейнера удобен host networking на Linux;
доступ из отдельной Docker-сети/LAN требует отдельного gateway/firewall с разрешёнными
клиентами. CLI намеренно отвергает non-loopback bind; не открывай этот no-auth proxy всему LAN.
Источник: [ultra-client](../cmd/ultra-client/main.go).

## Приёмка клиента

Локальные тесты проверяют закреплённый Xray; они не заменяют проверку приложений Happ.
Пока версия не записана после реального испытания, платформа не считается принятой:

| Платформа | Проверенная версия Happ | Импорт / XHTTP extra / обновление / ручной резерв |
| --- | --- | --- |
| Android | не проверена | требуется проверка на устройстве |
| iOS / iPadOS | не проверена | требуется проверка на устройстве |
| macOS | не проверена | требуется проверка в приложении |
| Windows | не проверена | требуется проверка в приложении |
| Linux | не проверена | требуется проверка в приложении |

На каждой платформе проверь DNS и охват приложений в VPN/TUN-режиме. URI не управляет
системной DNS-политикой Happ. Для проксируемых назначений нужен удалённый DNS без системного
fallback; автоматические исключения российских приложений ultra не добавляет.
Для Gemini проверяй вход в аккаунт и отправку запроса: HTTP 200 стартовой страницы недостаточно.
Сравни маршрут и регион аккаунта с [официальными ограничениями Gemini](https://support.google.com/gemini/answer/14579026?hl=en).

## Личный кабинет и локации

Для приглашённых пользователей доступен [личный кабинет](enrollment.md): повторное
копирование возвращает прежнюю подписку. Профиль «Автоматически» использует настройку
Mini App; профиль конкретной локации действует на выбравшем его устройстве. При отказе
возможна другая страна. Кабинет показывает серверные маршруты, а не выбранный профиль
приложения. Добавленные локации появляются после обновления подписки.
