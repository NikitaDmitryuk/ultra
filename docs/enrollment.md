# Закрытая регистрация и личный кабинет

Кабинет открывается кнопкой «Мой VPN» в личном чате с ботом. Администратор может
переключаться между своим кабинетом и администрированием; административные права
сами по себе не создают VPN-доступ. Для себя можно выдать именное приглашение.

## Допуск

В разделе «Приглашения» администратор выбирает одну закрытую группу. Бот должен
быть её администратором. Общая ссылка проверяет Telegram ID через `getChatMember`
при первой регистрации: подходят участники, администраторы, владелец и ограниченные
участники с `is_member=true`. Ошибка Telegram не даёт доступа. Пересланная ссылка
не помогает постороннему; ID группы задаётся на сервере.

После регистрации выход из группы не отзывает доступ. Закрытие регистрации,
изменение группы или обновление общей ссылки также не отключают существующих пользователей.
Вступление в группу должны контролировать её администраторы.

Именное приглашение выдаётся через выбор аккаунта в боте или числовой Telegram ID
с подтверждением. Оно действует семь дней и только для указанного аккаунта; чужая
попытка не расходует ссылку. Приглашения VPN отделены от административных.

Повторная регистрация возвращает существующий кабинет, включая отключённый.
Ранее выданные вручную конфиги автоматически к кабинету не привязываются.

## Управление доступом

- «Отключить» закрывает подписку и исключает основной UUID и все его профили из ядра.
- «Включить» возвращает прежние ключи и подписку.
- «Сбросить» меняет UUID всех профилей и подписку, сохраняя Telegram-привязку.
  Пользователю понадобится повторный импорт на устройствах.

Состояние «Применяем изменение» означает, что запись сохранена, но применение
ядром ещё не подтверждено. Worker повторяет применение; нельзя объявлять
отключение завершённым по одной записи в БД. Изменение состава пользователей может
кратко прерывать чужие соединения при reload общего Xray.

Администраторы получают уведомление о регистрации через сохраняемую очередь.
Повторная доставка после сбоя возможна; сообщение не содержит подписку.

## Постоянная подписка

Владелец получает одну и ту же ссылку повторно, без ротации или reload. Ссылка —
секрет доступа: получатель может скопировать её другому человеку. Ограничений по IP
или числу своих устройств нет. Работа Happ описана в [инструкции](happ.md).

`ULTRA_SUBSCRIPTION_ENCRYPTION_KEY_FILE` указывает на JSON-файл вне БД:
`{"active":"v1","keys":{"v1":"<base64 от 32 случайных байт>"}}`.
Файл доступен только исполнителю и резервируется отдельно от БД. Токен хранится
как SHA-256 для проверки и AES-256-GCM для повторной выдачи; AAD связывает шифротекст
с владельцем. При смене ключа сохраняйте старые версии до переноса всех записей.
Без ключа старые подписки проверяются, но выдача и восстановление ссылки запрещены.
Старые записи только с хешем автоматически не перевыпускаются.

Личные API проверяют Telegram `initData` и берут владельца из подписи. Ответы
с секретами используют `no-store`; ссылки и `initData` не сохраняются в localStorage.
