# Закрытая регистрация и личный кабинет

Кабинет открывается кнопкой «Мой VPN» в личном чате с ботом. Администратор может
переключаться между своим кабинетом и администрированием; административные права
сами по себе не создают VPN-доступ. Для себя можно выдать именное приглашение.

## Допуск

В разделе «Приглашения» администратор выбирает одну закрытую группу. Бот должен
быть её администратором. Общая ссылка проверяет Telegram ID через `getChatMember`
при первой регистрации: подходят участники, администраторы, владелец и ограниченные
участники с `is_member=true`. Ошибка Telegram не даёт доступа. Пересланная ссылка
не помогает постороннему; ID группы задаётся на сервере.

После регистрации выход из группы не отзывает доступ. Закрытие регистрации,
изменение группы или обновление общей ссылки также не отключают существующих пользователей.
Вступление в группу должны контролировать её администраторы.

Именное приглашение выдаётся через выбор аккаунта в боте или числовой Telegram ID
с подтверждением. Оно действует семь дней и только для указанного аккаунта; чужая
попытка не расходует ссылку. Приглашения VPN отделены от административных.

Повторная регистрация возвращает существующий кабинет, включая отключённый.
Ранее выданные вручную конфиги автоматически к кабинету не привязываются.

## Управление доступом

- «Отключить» закрывает подписку и исключает основной UUID и все его профили из ядра.
- «Включить» возвращает прежние ключи и подписку.
- «Сбросить» меняет UUID всех профилей и подписку, сохраняя Telegram-привязку.
  Пользователю понадобится повторный импорт на устройствах.

Состояние «Применяем изменение» означает, что запись сохранена, но применение
ядром ещё не подтверждено. Worker повторяет применение; нельзя объявлять
отключение завершённым по одной записи в БД. Изменение состава пользователей может
кратко прерывать чужие соединения при reload общего Xray.

Администраторы получают уведомление о регистрации через сохраняемую очередь.
Повторная доставка после сбоя возможна; сообщение не содержит подписку.

## Личные уведомления

В личном кабинете доступны четыре независимые категории Telegram-уведомлений:
изменение данных подключения, отключение и восстановление доступа, блокировка
квотой и сбои VPN. Все категории изначально выключены; включение не рассылает
прошлые события. Настройки сохраняются при сбросе ключей. Отключённый пользователь
может менять свои настройки уведомлений.

Об изменении ключей или подписки администратором либо системой приходит пояснение,
актуальная ссылка и кнопка кабинета. Действие самого пользователя в кабинете
отдельным сообщением не дублируется. Изменение доступа должно быть подтверждено
ядром; запись ожидающего изменения в БД сама по себе не повод сообщать об успехе.
Квотное уведомление появляется только при блокировке всех доступных маршрутов,
а не при исчерпании одного выхода с рабочим резервом.

Об аварии сообщается после пяти минут подтверждённой полной недоступности VPN,
о восстановлении — после двух минут непрерывных успешных проверок и только
получившим сообщение о сбое. Повтор той же аварии в течение 30 минут после
восстановления не создаёт новую пару сообщений. Краткие сбои, переключения
на рабочий резерв и остаток трафика сообщений не создают. Ошибка управляющего
API не доказывает отказ VPN. Бот работает на bridge: при полном падении bridge
своевременная доставка не гарантируется.

Пользовательская очередь отделена от административной. Перед доставкой проверяются
актуальность события и настройки получателя; отменённые и заменённые события
не рассылаются. Повтор при неоднозначном ответе Telegram может дать дубликат.
Источник: [состояние и очередь](../internal/db/repo_personal_notifications.go).

## Постоянная подписка

Владелец получает одну и ту же ссылку повторно, без ротации или reload. Ссылка —
секрет доступа: получатель может скопировать её другому человеку. Ограничений по IP
или числу своих устройств нет. Работа Happ описана в [инструкции](happ.md).

`ULTRA_SUBSCRIPTION_ENCRYPTION_KEY_FILE` указывает на JSON-файл вне БД:
`{"active":"v1","keys":{"v1":"<base64 от 32 случайных байт>"}}`.
Авторитетный источник установщика — JSON-файл оператора вне репозитория, например
`~/.config/ultra/subscription-keys.json`, принадлежащий оператору с правами 0600.
В каноническом `install.config` задаётся только абсолютный путь
`ULTRA_SUBSCRIPTION_ENCRYPTION_KEY_FILE`; значения ключей не помещают в `.env`,
Git, build assets, Ansible variables, receipts или логи.

Чистый bootstrap и upgrade создают приватную копию для операции, передают
только её путь Ansible и устанавливают на bridge
`/var/lib/ultra-relay/automation/subscription-keys.json` владельца `ultra-relay`,
0600. Systemd drop-in содержит только этот фиксированный путь. Доставка скрыта
`no_log` и `diff: false`; временные копии удаляются после успешного применения.
При сбое они остаются приватными для точного retry; изменение исходного ring
внутри той же генерации отклоняется. Существующие версии на bridge сохраняются;
повторное использование ID с другими байтами отклоняется до замены файла.
Bootstrap фиксирует путь и отпечаток ring вместе с первоначальным inventory;
после установки ring и drop-in relay перезапускается. Совместимый rollback
не меняет этот отпечаток. Ранее замороженные bootstrap-задания без пути ring
сохраняют исходные входы: для доставки ring нужен последующий upgrade.
Rollback бинарников не удаляет ring и не откатывает выданные токены.

Токен хранится как SHA-256 для проверки и AES-256-GCM для повторной выдачи;
AAD связывает шифротекст с владельцем. Ротация добавляет новый уникальный ID и
меняет `active`; исходный файл и его отдельная зашифрованная резервная копия
должны сохранять все ранее использованные ID до переноса или перевыпуска всех
затронутых записей. Старый ID нельзя назначать новому ключу. Без соответствующего
ключа прежняя подписка продолжает проверяться по хешу, но восстановление её ссылки
запрещено; явный перевыпуск создаёт новую ссылку и отзывает старую.

В recovery выбирают точный bridge-путь ring как `optional_state_paths`,
а не весь каталог `automation`, содержащий credentials провайдера. Архив
шифруется операторскому age recipient до передачи на exit; drop-in с путём
должен восстанавливаться вместе с ним. Наличие настройки ещё не доказывает
восстановимость: нужен завершённый encrypted backup generation, включающий
этот файл. Операторский источник дополнительно резервируют зашифрованно вне
рабочей машины; доступ к age identity хранят отдельно от архива.

Личные API проверяют Telegram `initData` и берут владельца из подписи. Ответы
с секретами используют `no-store`; ссылки и `initData` не сохраняются в localStorage.

Источники: [бот](../internal/bot/members.go), [репозиторий](../internal/db/repo_members.go),
[применение](../internal/adminapi/members.go), [шифрование](../internal/subscriptionkey/key.go),
[хранение подписок](../internal/db/repo_subscription.go).

## Разрешение и использование

В списке людей разрешение («Доступ разрешён», «Доступ отозван», применение изменения)
показывается отдельно от использования. «Трафик за последние 2 мин» означает положительный
счётчик, а не открытый Happ или непрерывное подключение. Иначе показано время без трафика;
без истории — «Трафик ещё не зафиксирован». Список обновляется каждые 30 секунд.
Последнее использование берётся из `monthly_traffic.updated_at`: обновление происходит
только при ненулевой выборке счётчиков, с агрегацией UUID профилей на владельца.
Метка сохраняется после очистки подробных samples и сброса UUID, поэтому описывает
историю доступа пользователя, а не факт первого использования конкретного нового конфига.
Источник: [сбор статистики](../internal/stats/collector.go),
[чтение участников](../internal/db/repo_members.go).

Закрытую группу можно выбрать штатной кнопкой Telegram `request_chat` из раздела
«Приглашения». Выбор привязан к администратору и одноразовому запросу на 10 минут;
после выбора отдельно подтверждается включение регистрации. Бот повторно проверяет
тип группы, отсутствие публичного username и свои права администратора.
[Telegram API](https://core.telegram.org/bots/api#keyboardbuttonrequestchat).

Участие в группе — отдельная информационная метка с временем проверки. Фоновая
проверка обрабатывает не более четырёх участников за цикл, успешный результат кешируется
на 5 минут; ошибка Telegram означает «Неизвестно». Смена группы сбрасывает кеш.
Проверка не меняет VPN-доступ и не задерживает открытие списка людей.

### Личная статистика

Кабинет читает статистику через `GET /api/self/traffic`: владельца определяет
проверенный Telegram ID, параметры UUID и чужие ID из запроса не используются.
Отозванный доступ сохраняет возможность просмотра своей истории. Ошибка статистики
не блокирует подключение Happ и получение подписки. Данные суммируются по всем
профилям и устройствам; время последнего трафика не означает, что устройство онлайн.

В карточке человека, личном кабинете и обзоре графики показывают только трафик,
для которого известен выход. Переключатель «День» использует почасовые счётчики
текущих суток UTC, «Месяц» — сохраняемые дневные агрегаты. Старые итоги без маршрута
остаются в БД и прежнем API, но не смешиваются с новыми графиками. Источник:
[member_traffic.go](../internal/db/member_traffic.go).

В графиках прямой маршрут называется «Напрямую с bridge». Узлы с одинаковыми
кодом страны и городом объединяются в одно направление, включая историю
отключённого узла после пересоздания. Совпадения отображаемого имени недостаточно:
без географических данных узлы остаются отдельными. Это только представление;
исходные теги, расходы и квоты каждого exit сохраняются отдельно. Фильтр направления
суммирует старые и новые точки в обоих периодах. Источники:
[API статистики](../internal/db/member_traffic.go),
[графики кабинета](../internal/bot/embed/miniapp/cabinet.js).

Имя из штатного выбора Telegram сохраняется вместе с приглашением (миграция 021).
После регистрации отображается актуальное имя кабинета. Имя и ссылка служат только
для навигации: проверка получателя по-прежнему выполняется по Telegram ID.
