# Перенос bridge при отдельной БД

PostgreSQL размещается на отдельном сервере и не переносится вместе с bridge.
IP и учётные данные БД сохраняются, приложения подключаются через закреплённый
SSH-туннель. Перенос VPN-хоста не должен восстанавливать старый дамп поверх общей
работающей БД.

Старый `ultra-install bridge-migrate` и связанные Ansible-операции отключены:
их протокол предусматривал перенос локального PostgreSQL и физические реплики.
Они требуют отдельной переработки перед применением к dedicated DB архитектуре.
Не запускайте прежние playbooks вручную и не сбрасывайте журнал незавершённой
операции для обхода этого ограничения.

Bootstrap поднимает новую БД либо применяет миграции через запуск relay.
Повторная установка с сохранением spec принимает только уже настроенный
DB-туннель. Перенос существующих данных выполняется явно и отдельно от
переноса bridge. Контракт: [отдельная БД](replication.md) и
[автоматизация](automation.md).

Аварийный [restore](../deploy/recovery/README.md) восстанавливает сохранённое
поколение на подготовленный bridge и дамп в явно выбранную пустую БД на
`database_target`. При пользовательских таблицах восстановление БД отказывает.
До активации relay восстанавливаются служебный ключ туннеля и закреплённые
host keys DB-сервера. Операторский SSH-ключ остаётся на операторской машине.
