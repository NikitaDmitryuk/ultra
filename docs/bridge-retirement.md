# Окончательное отключение старого bridge

Отключайте старую VM только после проверки нового primary, реальных PG-реплик,
свежих квот, HTTPS-входа и клиентских TCP/XHTTP-маршрутов. Успех API health сам по
себе не доказывает соединение устройства через новый адрес.

## Перед отключением

Проверьте статический IP нового bridge и backend отдельного HTTPS ingress.
URL подписки и DNS ingress сохраняются. Обновите существующую подписку в Happ
и переподключитесь: скачанные профили содержат IP bridge. Профили с прежним IP
после удаления пересылки перестанут работать.

Сохраните актуальный dump нового primary и прикладное состояние вне обеих VM,
с закрытыми правами доступа и SHA256. Проверьте восстановление в отдельную БД.
Замороженный старый PGDATA не является актуальным rollback после записей на новом primary.

Перед обновлением на VLESS-only штатно отключите SOCKS-клиентов через Admin API,
уберите `spec.socks5` и закройте прежние публичные SOCKS-порты. Архивные записи и
история остаются в БД. Внутренние прокси бота и WARP должны остаться работоспособны.
Сначала остановите бот, обновите relay, дождитесь Xray и проверьте маршруты,
затем запускайте бот. Сохраняйте прежние бинарники и конфигурацию до приёмки.

## Удаление

Остановите только `ultra-bridge-forward` на старом узле и повторите приёмку нового.
При ошибке возобновите пересылку; старый PostgreSQL не запускайте.
При успехе можно сразу остановить и удалить старую VM, затем её отдельный диск
и выделенный IP: ожидание миграции всех устройств не обязательно, если владелец
согласовал потерю доступа для необновлённых профилей.

Перед каждым удалением сверьте точный resource ID, адрес и принадлежность диска.
Общие сети, security groups, SSH-ключи и ресурсы нового сервера не удаляются.
Удалите только старый /32 из provider firewall, UFW exit и API allowlist Vultr,
сохранив доступ нового bridge. VPN exit и внутренний WARP не меняются.
Подтвердите отсутствие VM, диска и старого адреса в облачном инвентаре и повторите
проверки нового bridge после очистки доступов.

После удаления восстановление возможно из актуальной резервной копии; запуск
устаревшего старого primary или два одновременно работающих бота запрещены.
