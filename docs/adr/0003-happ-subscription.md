# 0003 — Отзываемая подписка Happ

## Статус

superseded

## Дата

2026-09-07

## Контекст

Для Happ нужен обновляемый список профилей без привязки базового подключения к платным
функциям. Ранее выданные VLESS-ссылки и поля `/client` должны сохраняться.

## Решение

Публичный HTTPS endpoint бота `/sub/{token}` возвращает список VLESS URI. Выпуск,
ротация и отзыв доступны администратору Mini App через защищённый Admin API.
Токен — случайные 32 байта в base64url; в PostgreSQL хранится только SHA-256.
Ссылка показывается только при выпуске/ротации. Ротация немедленно заменяет старый токен;
отключённый пользователь не получает подписку. Ответы не кешируются.
Публикуются только настроенные listeners и явно описанные резервные входы.
Основной TCP-профиль сохраняет UUID, порт, REALITY-ключи и старые поля API.

## Рассмотренные альтернативы

- UUID пользователя как токен: смешивает аутентификацию туннеля и доступ к подписке.
- Хранить исходную ссылку: увеличивает последствия чтения БД.
- Собственный мобильный клиент: не нужен для согласованного набора платформ.
- Платный выбор маршрутов Happ как обязательная зависимость: ручной выбор должен работать отдельно.

## Последствия

Подписка является bearer-секретом. Reverse proxy и журналы доступа не должны сохранять
полный путь `/sub/…`; HTTPS конфигурируется по существующей инструкции TLS.
Отзыв подписки запрещает обновление, но не аннулирует уже скачанные UUID/профили.
Для отзыва доступа к самому VPN отключают пользователя или меняют UUID.
Повторное включение пользователя возвращает доступ по неотозванному токену.
Требуется миграция 016. Удаление/ротация UUID каскадно удаляет его подписку.
Совместимость импорта XHTTP в конкретной версии Happ подтверждается отдельно на устройстве.
