# 0016 — Публичный доступ только через VLESS

## Статус

accepted

## Дата

2026-10-08

## Контекст

Пользовательский доступ обслуживается подписками Happ. Публичный SOCKS требовал
отдельных портов, паролей, UI и динамического firewall, хотя для выбранного сценария
он больше не нужен. Общий listener и индивидуальные клиенты имели независимые пути:
отключение `socks5.enabled` не отключало индивидуальные порты.

## Решение

Убираем публичный SOCKS из конфигурации, генерации Xray, выдачи клиентов и UI.
Пользователи создаются только как VLESS. Старые SOCKS-записи остаются архивными:
их нельзя включить, экспортировать как VLESS или использовать для нового listener.
Их история и схема БД сохраняются; штатное отключение выполняется до обновления.
SOCKS Telegram-бота, WARP exit и локального VPN-клиента остаётся внутренним механизмом.

## Рассмотренные альтернативы

Отключение только в текущей установке оставляло возможность повторного создания
клиентов и поддержку неиспользуемого транспорта. Владелец выбрал удаление из продукта.
Удаление старых записей и колонок не требуется и уничтожило бы историю.

## Последствия

Подписки, UUID и VLESS-контракт сохраняются. `kind=socks5` при создании получает 400;
включение архивного клиента — 409. Установщик больше не переносит `spec.socks5`.
При обновлении уберите этот блок из spec и закройте прежние публичные SOCKS-порты.
Потеря старого bridge IP требует обновления подписки и переподключения клиента,
даже если URL подписки остаётся на прежнем домене.
