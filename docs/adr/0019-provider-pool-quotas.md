# 0019 — Общая квота провайдера и личный потолок

## Статус

accepted

## Дата

2026-10-13

## Контекст

Vultr объединяет исходящий трафик аккаунта между экземплярами и регионами.
Личные лимиты по ID exit возвращали пользователю квоту при пересоздании.

## Решение

Заменяет бюджетную часть [ADR 0010](0010-monthly-quotas-and-route-application.md)
и [ADR 0014](0014-saved-vultr-plan-for-quotas.md). Месячная ёмкость равна
2 TB + 1 TB за каждый текущий экземпляр аккаунта, используя десятичные байты.
Считать все экземпляры из полного `/instances`, включая выключенные; удалённые,
исчезнувшие из списка, больше не дают ёмкость. Общий `gb_out` из
`/account/bandwidth` вычитать один раз. Удаление экземпляра не уменьшает уже
учтённый расход. Безопасный потолок — округлённые вниз 80% ёмкости; личный потолок
— 25% безопасного потолка. Период — календарный месяц UTC. Остаток не делить между exit.

`account_id` сохраняет личный расход при ротации и отзыве доступа. Принадлежность
физического exit к провайдеру сохраняется после удаления. Неопределённый расход
не исключается из расчёта молча: активация блокируется до установления источника.
История физических маршрутов не объединяется в виртуальный трафик пула.

Резервирование в bbolt одной транзакцией оплачивает личный потолок, общий пул и
физический маршрут. При переходе со старого состояния сначала берётся максимум
подтверждённого и локального расхода каждой пары «владелец—exit», затем сумма.
Общий резерв учитывает удалённых владельцев. В пакетах статистики остаются только
физические маршруты. Сохраняются 256 КиБ на пару и 24 часа автономности.

Внешнее наблюдение имеет локальную отметку, полученную до HTTP-запроса. Более
поздние списания уменьшают подтверждённый остаток. Ошибка API не обновляет срок
наблюдения. Аварийные 5 ГБ на exit дополнительно ограничены личной квотой и общим
пулом; новый exit без подтверждения не получает аварийный запас. Служебный монитор
сохраняет отдельный предел на каждом exit и также оплачивает общий пул.

Снимок версии 3 и capability `provider-pool-quota-v1` необходимы для нового режима.
Управляемый systemd unit передаёт `-require-provider-pool-quota`: несовместимый
бинарник отвергает неизвестный флаг. Аварийный бинарник должен поддерживать пул и
журнал; возврат к старой политике квот после активации не является допустимым откатом.

## Рассмотренные альтернативы

- Привязка личной квоты к локации: смена региона всё ещё возвращает лимит.
- Деление общего остатка между exit: искусственно ограничивает исправный маршрут.
- Вычитать расход по каждому exit: Vultr уже предоставляет общий месячный расход,
  а сумма по узлам создаёт двойной учёт и теряет трафик после удаления.
- Удаление старых счётчиков: теряет расходы заменённых узлов и поздние пакеты.

## Последствия

Добавление и замена серверов не обновляют личный остаток. Исчерпание общего пула
исключает все выходы этого провайдера; ручной резерв учитывается отдельно.
Измеренные полезные байты обоих направлений и консервативные списания отличаются
от биллинга провайдера по исходящему трафику; запас сохраняется.
Подписки показывают личный потолок и расход через `subscription-userinfo`;
доступный остаток дополнительно ограничен общим бюджетом и состоянием маршрутов.
Автономный кеш публикует последние подтверждённые значения с отметкой устаревания.
