# 0012. HTTPS-вход на постоянном узле

## Статус
accepted

## Дата
2026-09-08

## Контекст
Сменный дополнительный exit не подходит для роли входа подписок: такое размещение
связывает удаление VPS с доступностью Mini App и обновлением Happ.
На постоянном ingress-узле уже настроен nginx для TCP-проксирования
и HTTP-01 на bridge. Прежний сторонний сервис на публичном HTTPS-порту больше не нужен.

## Решение
Заменяет [ADR 0011](0011-subscription-ingress.md) в выборе узла и способа установки.
Использовать nginx постоянного ingress-узла как вход 443/8444, сохранив бота, БД,
сертификат и проверку подписок на bridge. Посторонние VPN-сервисы исключить из управляемого пути; ultra и WARP
сохранить. Для существующего сервера использовать отдельный SSH-режим установщика,
не зависящий от Vultr. Прежний режим HAProxy/Vultr остаётся доступным.
Прежний вход освобождать от служебной роли только после проверки DNS-перехода и работы
подписок при остановленном старом HTTPS-прокси.

## Рассмотренные альтернативы
Оставить вход на сменном VPS — сохранить нежелательную зависимость.
Разделять 443 по SNI со сторонним сервисом — дополнительная сложность.
Оставить только 8444 — сохраняет нестандартный порт в новых публичных ссылках.
Переносить бота и БД — не требуется для изменения HTTPS-входа.

## Последствия
Дополнительный Vultr VPS можно удалять независимо от подписок после завершения
переноса. Постоянный ingress-узел и bridge остаются обязательными: резервирования бота нет.
Старые ссылки, токены и UUID не меняются. На время DNS-кеширования оба входа
работают, а сменный VPS остаётся защищённым от удаления. Сторонний сервис не является вариантом
отката: откатывается только HTTPS-вход.
