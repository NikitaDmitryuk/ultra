# 0021 — PostgreSQL на отдельном сервере

## Статус

superseded (2026-10-16): отдельный primary с async standby на bridge.

## Заменено

[0022 — Реплика PostgreSQL на bridge](0022-bridge-postgres-replica.md).

## Дата

2026-10-15

## Контекст

Для небольшого количества пользователей поддержка PostgreSQL на VPN-узлах и
физических реплик усложняет установку, обновление и восстановление. Перенос bridge
не должен изменять общую БД.

## Решение

Поддерживается один отдельный DB-хост с явным IP и операторским SSH-доступом в
каноническом `install.config`. Ansible устанавливает PostgreSQL и создаёт
отсутствующие роль и БД; relay применяет нумерованные миграции. Bridge подключается
через закреплённый SSH-туннель. PostgreSQL слушает только loopback DB-хоста.
Логические резервные копии шифруются и доставляются на другие доступные узлы.
Восстановление дампа допускается только в пустую dedicated БД.

## Рассмотренные альтернативы

Совместное размещение с VPN и физическая репликация исключены из поддерживаемых
сценариев по решению владельца проекта. Управляемая внешняя БД не обязательна:
установка использует обычный сервер с PostgreSQL.

## Последствия

DB-хост остаётся единственной точкой записи; при его отказе требуется восстановление
из копии. Его IP и ключ доступа независимы от bridge и exit. Прежний bridge-migrate,
перемещавший PostgreSQL вместе с VPN, отключён. Замена VPN-хоста должна сохранять
БД и пересоздавать только защищённое подключение к ней.
