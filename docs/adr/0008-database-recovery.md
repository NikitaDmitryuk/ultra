# 0008 — Асинхронные копии БД и ручное восстановление

## Статус

superseded (2026-10-15): отдельный DB-хост и логические резервные копии.

## Заменено

[0021 — PostgreSQL на отдельном сервере](0021-dedicated-database.md).

## Дата

2026-09-07

## Контекст

Нужны копии данных на подходящих узлах без второго центра записи и автоматического переключения БД.

## Решение

Прежнее решение: основная БД остаётся на bridge. Worker поддерживает физические реплики PostgreSQL через SSH на узлах с достаточным диском и совместимой архитектурой. Promotion и восстановление выполняются вручную. Кластер Ultra отделён от существующих данных узла; удержание WAL ограничено.

## Рассмотренные альтернативы

Multi-master и автоматический failover не выбраны. Только периодические дампы не дают непрерывно обновляемой копии, но нужны дополнительно как независимые резервные копии.

## Последствия

Возможна потеря последних транзакций. После длительного разрыва может понадобиться новая базовая копия. Реплика не заменяет backup и не содержит внешние серверные ключи. Старый primary необходимо изолировать до promotion.

## Источники

Действующий контракт: [отдельная БД](../replication.md). Прежние worker и Ansible-роли
физической репликации удалены; PostgreSQL на VPN-хостах больше не поддерживается.
Пользовательские данные сохраняются на одном отдельном DB-сервере, логические
зашифрованные копии доставляются на другие доступные узлы.
