# 0008 — Асинхронные копии БД и ручное восстановление

## Статус

accepted

## Дата

2026-09-07

## Контекст

Нужны копии данных на подходящих узлах без второго центра записи и автоматического переключения БД.

## Решение

Основная БД остаётся на bridge. Worker поддерживает физические реплики PostgreSQL через SSH на узлах с достаточным диском и совместимой архитектурой. Promotion и восстановление выполняются вручную. Кластер Ultra отделён от существующих данных узла; удержание WAL ограничено.

## Рассмотренные альтернативы

Multi-master и автоматический failover не выбраны. Только периодические дампы не дают непрерывно обновляемой копии, но нужны дополнительно как независимые резервные копии.

## Последствия

Возможна потеря последних транзакций. После длительного разрыва может понадобиться новая базовая копия. Реплика не заменяет backup и не содержит внешние серверные ключи. Старый primary необходимо изолировать до promotion.
