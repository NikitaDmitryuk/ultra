# 0020 — Общий исполнитель инфраструктуры Ansible

## Статус

accepted

## Дата

2026-10-13

## Контекст

CLI, cloud provisioner и recovery controller имеют отдельные реализации настройки
файлов и служб. Повторяемые инфраструктурные действия требуют единого источника,
а перезапуск relay не должен прерывать принятую настройку узла.

## Решение

Переносим настройку инфраструктуры в общие роли Ansible. Независимый systemd worker
на bridge принимает ограниченные операции и сохраняет приватные задания до запуска.
Локальный CLI остаётся точкой входа для bootstrap и восстановления. `.env` и
`install.config` сохраняют назначение; inventory является производным состоянием.
Прикладные форматы копий, облачный журнал, квоты и маршрутизация остаются кодом ultra.

## Рассмотренные альтернативы

Terraform предназначен для управления облачными ресурсами и не заменяет конфигурацию
приложения. Docker/Kamal потребовал бы отдельной миграции упаковки. Сохранение нескольких
установщиков за Ansible wrapper оставляет исходное дублирование поведения.

## Последствия

Нужны закреплённый runtime, проверка идемпотентности и независимость worker от relay.
Ansible сам по себе не обеспечивает совместимость ledger, транзакционный откат и
продолжение после аварии: эти проверки остаются явными контрактами ultra.
Переход включается по проверенным операциям; текущие границы реализации описывает
автоматизация, а не статус этого ADR.
