# 0004 — Резерв по месту измеренного отказа

## Статус

accepted

## Дата

2026-09-07

## Контекст

Маршрут имеет два независимо фильтруемых участка: устройство → bridge и bridge → exit.
Один дополнительный сервер не устраняет одновременно отказы обоих участков.

## Решение

Выбирать размещение дополнительного узла после измерений. Для отказа входного IP —
TCP passthrough в другом ASN на существующий bridge, без второй БД. Для отказа
межузлового канала или exit — второй exit у другого провайдера. До подтверждения
доступности не добавлять маршрут в публичную подписку.

`public_entries` описывает уже подготовленные TCP-перенаправления и стабильные ID;
это экспорт профилей, а не автоматическая покупка/установка/проверка нового узла.
Разрешены отдельные внешние порты для существующих TCP, XHTTP/REALITY и XHTTP/TLS listeners.
SNI, сертификат, UUID и REALITY-ключи остаются от bridge: TLS на passthrough не завершается.

## Рассмотренные альтернативы

- Второй полноценный bridge: добавляет согласование пользователей и состояния БД.
- Второй exit независимо от причины: не помогает при недоступном входном IP.
- Смена только SNI: не обеспечивает достижимость IP при адресных белых списках.

## Последствия

Пока место отказа не подтверждено, конкретная новая топология не выбрана и узлы не создаются.
Вход через passthrough сохраняет зависимость от прежнего bridge. Рабочие соединения
не переносятся между профилями; ручной выбор резерва в Happ — отдельное подключение.
Для резервного входа нужно проверить полный путь в целевой сети, защитить forwarding
от посторонних назначений и зафиксировать способ отката до публикации.
