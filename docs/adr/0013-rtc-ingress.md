# 0013 — RTC как опциональный персональный вход

## Статус
accepted

## Дата
2026-09-10

## Контекст
Нужен аварийный TCP-доступ для зарегистрированных пользователей без перезагрузки общего
Xray при смене комнаты и без повторного списания трафика из квоты.

## Решение
Весь модуль включается одним флагом, по умолчанию выключен. Инструкции и внешние ссылки
поступают из приватного конфига. Комнаты и ключи шифруются в PostgreSQL существующим AEAD
с отдельным контекстом; HMAC комнаты позволяет обеспечить уникальность без открытого ID.

Динамический SOCKS gateway передаёт серверную личность владельца в существующую маршрутизацию.
Отдельный непривилегированный supervisor управляет транспортами через Unix-сокет.
Лимит резервируется транзакционно, доступ меняется по поколениям, отзыв закрывает
только соответствующие сокеты. Контрольный клиент проверяет фактическую передачу.

Диагностический учёт RTC-входа отделён от существующих таблиц списания: повторное
использование обычного `RecordSamples` увеличило бы квоты второй раз. Почасовые
накопительные счётчики сохраняются идемпотентно по владельцу, часу и эпохе сборщика.

## Последствия
Первый переход с пилота требует остановки старых служб и одного перезапуска relay.
Пилотные ключи импортируются с сохранением клиентского профиля. Дальнейшее изменение
комнаты не меняет Xray-конфигурацию. Без флага private config и runtime не требуются.
Провайдер видит bridge; работа сервиса конференций сама по себе не гарантирует
доступность его медиасерверов при ограничениях. Прикладной UDP не поддерживается.

Контракт и эксплуатация: [RTC](../rtc.md).

## Рассмотренные альтернативы
Персональные статические Xray-inbound из пилота требуют общего reload при изменении
комнаты. Их заменяет динамический gateway. Хранение диагностического входа в обычной
таблице трафика отклонено из-за повторного списания квот.
