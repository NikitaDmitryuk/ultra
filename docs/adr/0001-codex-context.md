# 0001 — Контекст Codex в репозитории

## Статус

accepted

## Дата

2026-09-07

## Контекст

Агентам ultra нужен общий контекст, доступный в новом checkout без истории прошлых
разговоров. Сохранение всех результатов задач создаёт шум и устаревающие инструкции.
Владелец проекта согласовал репозиторный harness только для Codex: инструкции и CI,
русский язык, один начальный ADR и карта текущей архитектуры без ретроспективных решений.

## Решение

Храним короткий `AGENTS.md` как вход в тематические документы и ADR. Codex после
значимого проверенного изменения и перед завершением задачи оценивает новые знания:
сохраняет только специфичные для проекта, подтверждённые и полезные будущим задачам.
Сначала обновляет существующее описание и удаляет устаревшее. Отсутствие новой записи
нормально, если нового устойчивого знания нет.

Архитектура хранит карту системы, руководство разработки — воспроизводимые особенности
работы, ADR — значимые решения с причинами. Логи, планы и результаты отдельных задач
остаются в задаче или PR. Graphify служит необязательным локальным индексом, а не
каноническим источником знаний.

Локальная команда `make harness-check` и CI проверяют структуру и навигацию. Полезность
и соответствие коду оценивают агент и ревьюер. Автоматической записи после каждой задачи,
клиентских хуков, фоновой LLM-обработки и внешнего сервиса памяти нет.

## Рассмотренные альтернативы

- Один большой файл памяти: прост для добавления текста, но раздувает начальный контекст
  и затрудняет удаление дублей и устаревших правил.
- Обязательная заметка или ADR на каждую задачу: создаёт документы ради прохождения проверки.
- Клиентские хуки и внешняя память: требуют дополнительной настройки и сопровождения;
  выбранный процесс должен работать через репозиторные инструкции и CI.
- Несколько адаптеров клиентов: сейчас нужен только Codex; общая документация остаётся обычным Markdown.

## Последствия

Новая сессия получает стабильную точку входа, а детали читает по необходимости.
Контекст развивается вместе с изменением и остаётся доступен в Git. Возникает обязанность
обновлять затронутые документы и сохранять историю решений при их замене.

Инструкция не гарантирует выполнение шага каждым запуском модели, а структурный CI
не доказывает полезность текста. Нельзя считать отсутствие ошибки проверки доказательством
актуальности документации. Проблемы соблюдения процесса сначала исправляем точечными
правилами или проверками; расширение автоматизации потребует нового решения.
