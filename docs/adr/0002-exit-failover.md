# 0002 — Failover по передаче полезных данных

## Статус

accepted

## Дата

2026-09-07

## Контекст

TCP connect не доказывает прохождение туннеля. Пересоздание Xray прерывает соединения,
поэтому RTT и время измерения не должны менять конфигурацию. Владелец согласовал
проверки тела HTTPS, ограничение ожидания и задержку возврата к preferred exit.

## Решение

Один worker каждые 10 секунд выполняет цикл с deadline 8 секунд, максимум четыре exit
одновременно. Каждый проверяется через свой outbound работающего Xray: два независимых
HTTPS-ответа ровно по 64 КиБ, успех одного достаточен. TCP-диагностика ограничена 3 секундами.
Два неудачных цикла исключают exit, три успешных восстанавливают; возврат к preferred
требует 60 секунд устойчивости. При старте сохраняем существующие маршруты до двух неудач; диагностические поля показывают измерения.
При отказе всех exit сохраняется туннельный маршрут и выставляется degraded.

Измерения и эффективные маршруты разделены. Сборка и применение сериализованы,
эквивалентный разобранный config не перезапускает Xray. Проверяем новую конфигурацию
до закрытия старого экземпляра; при ошибке запуска восстанавливаем старую и явно
сообщаем об ошибке восстановления. Неудавшееся применение повторяется worker.

## Рассмотренные альтернативы

- TCP-only health: не обнаруживает остановку передачи после первых килобайт.
- Reload при каждом измерении: рвёт рабочие соединения без смены маршрута.
- Отдельное ядро на каждую проверку: лишние ресурсы и другая конфигурация пути.
- Прямой выход при отказе всех exit: нарушает выбранный пользователем маршрут.

## Последствия

При уже исправном резерве два цикла дают бюджет обнаружения до 28 секунд для пула
до четырёх exit, без учёта времени применения конфигурации. Общий предел 30 секунд
нужно подтвердить на узле: загрузка geo и старт Xray также занимают время.
Более четырёх exit делят общий бюджет цикла; увеличение пула требует измерения
и пересмотра расписания. Сами проверки расходуют до 128 КиБ на exit за цикл.
Смена реального маршрута по-прежнему может прервать соединения; rollback не возвращает
уже закрытые TCP-сессии. Успех контрольных адресов не гарантирует доступность каждого сайта.
