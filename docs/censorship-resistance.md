# Обход цензуры: механизмы и границы

Код не гарантирует доступность в каждой сети. Настройки установки — в [README](../README.md)
и [TLS](../deploy/TLS.md), клиентские процедуры — в [Happ и домашнем прокси](happ.md).
При изменении генератора проверяй конфигурацию закреплённым в [go.mod](../go.mod) Xray.

## Участки соединения

- Устройство → bridge: TCP/REALITY/Vision; при настроенном listener — XHTTP/REALITY
  или XHTTP/TLS. Смена exit не исправляет блокировку входного IP.
- Bridge → exit: XHTTP (`splithttp`, по умолчанию `stream-up`/H2) либо gRPC.
  `mimic_preset` задаёт HTTP-форму, но не означает передачу через разрешённую инфраструктуру Steam/CDN.
- При split routing `direct` означает выход из сети bridge, например Yandex Cloud.
  `blocklist` отправляет на exit совпадения со списками; `ru_direct` меняет правило
  по умолчанию; `split_routing: false` отправляет весь пользовательский трафик на exit.
- Gemini, AI Studio, Generative Language API, Google Accounts, googleusercontent и gstatic
  направляются на exit до стандартных географических правил. Явные `domain_direct`
  имеют прежний приоритет: при неисправности Gemini сначала проверь эти исключения.
- WARP на exit проксирует TCP; UDP идёт напрямую с exit. Успех прямого HTTP-запроса
  не подтверждает здоровье WARP. Изменение режима всем пользователям требует отдельных измерений.

Источники: [маршрутизация](../internal/config/bridge_routing.go),
[exit builder](../internal/config/xray_exit.go), [профили](../internal/config/xray_client.go).

## Транспорт и совместимость

Используется `xPaddingBytes`, стандарт 100–1000. Старые значения `0`, `0-64`, `0-100`,
`0-128` нормализуются с предупреждением: прежнее поле `xPaddingSize` ядро игнорировало.
Иные диапазоны должны быть положительными, не более 65536 и включать 100–1000,
чтобы принимать уже выданные клиентские конфигурации. Оба конца межузлового туннеля
обновляй согласованно; стандартный диапазон совместим с прежним игнорируемым полем.

`fragment` в sockopt отсутствует. Явный `anti_censor.fragment.packets` включает экспериментальную
цепочку `dialerProxy` → freedom с fragment, только для bridge → exit; по умолчанию выключена.
Это фрагментация транспортного handshake, а не универсальный обход ограничений после 16 КиБ.
`scMaxEachPostBytes` применяется только в `packet-up`; `stream-up` его не использует.
Fingerprint клиента выбирается из явного значения/первого элемента пула/`chrome`;
серверный inbound не ротирует ClientHello клиента.

Путь туннеля следует задавать одинаковым `splithttp_path` на двух узлах. Пустой путь
теперь стабилен (`/xhttp`), чтобы случайная генерация не вызывала reload. Если раньше
на одной стороне был пустой путь, перед обновлением зафиксируй фактически согласованный
путь на обеих; работа старых случайных путей не гарантировалась.
Источники: [генератор](../internal/config/xray_helpers.go),
[локальные передачи трёх профилей](../internal/config/profile_integration_test.go),
[XHTTP от разработчиков](https://github.com/XTLS/Xray-core/discussions/4113).

## Health и DNS

Worker проверяет каждый outbound работающего ядра: два HTTPS-тела по 64 КиБ, успех одного
достаточен. TCP timeout 3 секунды, общий цикл 8 секунд, период 10 секунд, параллелизм 4.
При старте существующие маршруты сохраняются до двух измеренных неудач. Затем для
восстановления нужны три успеха, для возврата к предпочтительному exit — 60 секунд стабильности.
При отказе всех exit остаётся туннельный маршрут и degraded. RTT/CheckedAt не вызывают reload;
реальное переключение может прервать TCP. См. [ADR failover](adr/0002-exit-failover.md).

Маршрутизация использует `AsIs`: имена VPN-назначений передаются на exit. DNS инфраструктуры
(адрес bridge/exit, bootstrap DoH) отделён от имён пользовательских назначений. Freedom
использует встроенный DoH через `ForceIPv4`, без системного fallback; при WARP имя передаётся
SOCKS на exit. `dev_mode` и явный `disable_doh` — исключения с системным разрешением.
Это не настраивает DNS устройства: режим Happ/TUN и `socks5h` проверяются отдельно.
Источники: [DNS](../internal/config/xray_dns.go), [health](../internal/proxy/health.go).

## Измерения и выпуск

`make build-bench` собирает локальную утилиту без SSH и изменения узлов:

```sh
./ultra-bench -repeat 5 -streams 1 > direct.jsonl
./ultra-bench -proxy socks5h://127.0.0.1:10808 -repeat 5 -streams 1 > tunnel.jsonl
./ultra-bench -proxy socks5h://127.0.0.1:10808 -streams 4 -duration 5m > sustained.jsonl
```

Для скорости задай `-urls` с большим контролируемым HTTPS-файлом. Стандартные адреса
проверяют короткие 64 КиБ ответы и Gemini. `-duration 5m` повторяет запросы пять минут;
это не одно непрерывное TCP-соединение. Для проверки одного долгого потока используй
контролируемый большой файл и внешний curl с `--max-time 300`, а результат timeout
различай с ошибкой передачи. JSONL содержит HTTP-код, байты, время до DNS/connect/TLS/первого
байта (от начала запроса), скорость по секундам, медиану/p95 и долю ошибок.
DNS/connect могут относиться к прокси; удалённые DNS/TCP-фазы внутри туннеля клиенту не видны.

[SSH benchmark](../scripts/benchmark-relay.sh) отдельно сравнивает bridge → exit,
exit напрямую/WARP; запускается только при разрешённой диагностике узлов.
Сопоставляй UTC-время ошибок приложения, health и reload с CPU/RAM/FD/retransmissions.
Серверные запросы не заменяют проверку из пользовательской Wi-Fi/мобильной сети.
Не сохраняй исходные spec, токены, IP пользователей и сырые логи в документацию.

Сначала отдельный тестовый пользователь и откат (прежний бинарник/spec/основной профиль),
затем минимум пять повторов и пятиминутные передачи. Суточное наблюдение должно подтвердить:
нет обрывов от неизменного health, переключение при исправном резерве ≤30 секунд,
медианная скорость контрольного маршрута не хуже более чем на 10%. Отсутствие воспроизведения
не доказывает исправление. Выбор дополнительного узла — по [ADR топологии](adr/0004-reserve-topology.md).
