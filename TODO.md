# Приёмка Ansible и обновления из GitHub Releases

Этот список фиксирует оставшуюся эксплуатационную приёмку по [#37](https://github.com/NikitaDmitryuk/ultra/issues/37),
[#40](https://github.com/NikitaDmitryuk/ultra/issues/40) и [#42](https://github.com/NikitaDmitryuk/ultra/issues/42),
а не задачи реализации.
CLI загружает и проверяет подписанные GitHub Releases, а `upgrade` без `--config`
читает локальный `install.config`; поведение описано в [руководстве Ansible](docs/automation.md)
и реализовано в `cmd/ultra-install/automation.go` и `github_release.go`. Это само по себе
не подтверждает сохранение фактических установленных настроек при таком обновлении.
Сквозные проверки выполнять только на изолированной VM-топологии, не на production.

- [ ] По [#40](https://github.com/NikitaDmitryuk/ultra/issues/40) принять обновление
  на VM: `latest`, конкретный tag, сохранение установленной конфигурации без нового
  config и применение явно переданного config; проверить отказ до установки для
  неверной подписи/комплекта и безопасный rollback при ошибке применения.
- [ ] По [#42](https://github.com/NikitaDmitryuk/ultra/issues/42) создать
  воспроизводимую изолированную VM-топологию и автоматизированную матрицу:
  реальные systemd-службы и туннель, установка/обновление, rollback, перезапуск
  контроллера и потеря SSH во время соответствующих операций, включая восстановление.
- [ ] Выполнить полный переход на canonical production domain, заданный в
  приватном `install.config`; проверить DNS/TLS, ingress и ссылки подписок.
  Автоматическая очистка текущего cutover ограничена DNS/Nginx-ресурсами из
  receipt этой транзакции; если DNS не менялся, retirement не запускается.
  После проверки нового endpoint отдельно инвентаризировать и удалить исторические
  DNS-ресурсы и Nginx-конфиги вроде `ultra-domain-alias-*` и
  `ultra-vpn-legacy.conf`, включая ресурсы из прежних receipts. Другие service
  domains и legacy aliases не поддерживать.
- [ ] В учении восстановления поднять актуальное зашифрованное поколение в
  изолированной VM и проверить данные, ключи, подписки, автоматизацию и независимую копию.
- [ ] В изолированной среде проверить cutover и перенос bridge, сохранив rollback
  и комплекты миграции до окончания срока их использования для отката.
- [ ] Проверить завершение и очистку низкоуровневых заданий, сырых установок без
  manifest, `domain-cutover` и configured ingress. Не удалять неизвестные файлы
  по имени каталога и не считать успех отдельного Ansible-этапа успехом операции.

Issue #39 закрыт; её работа с флагами и метаданными HAPP не входит в Ansible-приёмку.
Issues #43–#45 относятся к сообщениям и пользовательским алертам Mini App и также
не входят в этот список. Issue #38 удалён. Контракты безопасности, сохранности
данных и совместимости rollback остаются обязательными при любой приёмке;
их текущее устройство описано в [автоматизации](docs/automation.md).
